# API

Интерактивная документация — Swagger на `/docs`, схема — `/openapi.json`.
Базовый адрес при локальном запуске: `http://127.0.0.1:8000`.

## Каталог сценариев

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/scenarios` | список ситуаций для экрана выбора |
| `GET` | `/api/scenarios/{scenario_id}` | карточка ситуации |
| `GET` | `/api/scenarios/{scenario_id}/source` | исходный JSON сценария — показать методисту или жюри, как описано содержание |
| `POST` | `/api/scenarios/reload` | перечитать JSON-сценарии без перезапуска сервера |

`POST /api/scenarios/reload` заодно проверяет сценарии: если после правки
появилась ссылка на несуществующий узел или недостижимая ветка, придёт `400` с
описанием проблемы, а рабочий каталог останется прежним.

## Прохождение

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/attempts` | начать сценарий |
| `GET` | `/api/attempts/{attempt_id}` | текущее состояние попытки |
| `POST` | `/api/attempts/{attempt_id}/choice` | принять решение |
| `POST` | `/api/attempts/{attempt_id}/timeout` | сообщить, что время на экране вышло |

Старт попытки:

```bash
curl -X POST http://127.0.0.1:8000/api/attempts \
  -H "Content-Type: application/json" \
  -d '{"employee_id": 1, "scenario_id": "two_passengers_one_seat"}'
```

Ответ (сокращённо):

```json
{
  "attempt_id": 12,
  "employee_id": 1,
  "scenario": { "id": "two_passengers_one_seat", "title": "Двое на одно место", "car": "Вагон 5", "service_class": "комфорт" },
  "loyalty": 70,
  "safety": 80,
  "finished": false,
  "steps_taken": 0,
  "node": {
    "id": "s1_meet",
    "kind": "situation",
    "narration": "Поезд идёт на 350 км/ч...",
    "passenger": "«Это моё место, у меня билет!»",
    "timer_seconds": 25,
    "deadline_at": "2026-09-27T09:14:32+00:00",
    "options": [
      { "id": "check_tickets", "text": "«Добрый день. Позвольте Ваши билеты, я сверю места.»" }
    ]
  },
  "server_time": "2026-09-27T09:14:05+00:00"
}
```

Вариант приходит **без** качества и эффектов: правильный ответ нельзя подсмотреть
в ответе API. Разбор шага появляется в `last_step` уже после выбора.

Таймер клиент рисует как `deadline_at` минус `server_time`, поэтому расхождение
часов на машине проводника ни на что не влияет. Решение об истечении времени
принимает сервер: если выбор придёт после дедлайна, он будет обработан как
таймаут.

Решение:

```bash
curl -X POST http://127.0.0.1:8000/api/attempts/12/choice \
  -H "Content-Type: application/json" \
  -d '{"option_id": "check_tickets"}'
```

В ответе — те же поля плюс `last_step` с разбором шага:

```json
{
  "loyalty": 75,
  "safety": 86,
  "steps_taken": 1,
  "last_step": {
    "node_id": "s1_meet",
    "choice_text": "«Добрый день. Позвольте Ваши билеты, я сверю вагон и место и помогу разобраться».",
    "option_id": "check_tickets",
    "timed_out": false,
    "quality": "optimal",
    "loyalty_delta": 5,
    "safety_delta": 6,
    "loyalty_after": 75,
    "safety_after": 86,
    "competency_gain": { "conflict": 3, "regulations": 2, "time_pressure": 1 },
    "debrief": "Вы признали ситуацию и сразу перешли к проверке документов, не встав ни на чью сторону."
  }
}
```

`quality` принимает значения `optimal`, `acceptable` и `harmful`. Очко
компетенции «Решение в дефиците времени» добавляется за решение, принятое до
истечения таймера.

Когда попытка доходит до узла-исхода, `finished` становится `true`, а в ответе
появляется `debrief`: вердикт, обе шкалы, число таймаутов и ошибочных решений,
очки компетенций, начисленный опыт, новые достижения и полный путь решений.

## Профиль, рейтинг, аналитика

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/employees` | список проводников демо-среды |
| `GET` | `/api/employees/{employee_id}/profile` | уровень, опыт, компетенции, достижения |
| `GET` | `/api/employees/{employee_id}/attempts` | история попыток |
| `GET` | `/api/employees/{employee_id}/analytics` | пробелы в компетенциях и рекомендации |
| `GET` | `/api/employees/{employee_id}/notifications` | уведомления |
| `POST` | `/api/notifications/{notification_id}/read` | отметить уведомление прочитанным |
| `GET` | `/api/leaderboard?scope=brigade&employee_id=1` | рейтинг: `brigade`, `depot`, `company` |

Для срезов `brigade` и `depot` нужен `employee_id` — от него берётся бригада или
депо. Без него придёт `422`.

## Интеграции

Контракты описаны и работают на демо-данных, реальных подключений в прототипе нет.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/integrations/hr/employees` | принять сотрудника из HR-системы |
| `GET` | `/api/integrations/lms/results/{employee_id}` | отдать результаты обучения в LMS |

```bash
curl -X POST http://127.0.0.1:8000/api/integrations/hr/employees \
  -H "Content-Type: application/json" \
  -d '{"hr_ref": "HR-4821", "login": "demo.ivanov", "display_name": "К. Иванов (демо)", "brigade": "Бригада 3", "depot": "Депо Москва-Восточное"}'
```

Сотрудник создаётся или обновляется по логину. Прогресс при обновлении не
сбрасывается: меняются только кадровые поля.

Выгрузка в LMS отдаёт уровень, опыт, очки компетенций, коды достижений и
завершённые попытки с результатом и обеими шкалами.

## Служебное

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | готовность сервиса и число загруженных сценариев |

## Коды ошибок

| Код | Когда |
|---|---|
| `400` | недопустимое действие: попытка уже завершена, неизвестный вариант, сценарий не прошёл проверку при перезагрузке |
| `404` | не найдены попытка, сценарий, проводник или уведомление |
| `422` | не хватает параметра запроса или тело не соответствует схеме |

Ошибки приходят в виде `{"detail": "текст на русском"}` — сообщение можно
показать проводнику как есть.
